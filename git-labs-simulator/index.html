Biblioteca de Padrões & Conventional Commits

Por que adotamos Conventional Commits na Indústria?

O Conventional Commits é uma especificação padronizada para mensagens de commit em equipes de tecnologia. Ele cria um histórico legível para humanos e computadores, permitindo:

🤖 Automação de Releases Geração automática de notas de versão (CHANGELOG.md).
🔢 Semantic Versioning Decide se a versão sobe MAJOR, MINOR ou PATCH.
🔍 Code Review Ágil Compreensão instantânea do escopo e intenção do autor.

Estrutura Oficial de um Commit Padronizado

<tipo>[escopo opcional][!]: <descrição imperativa minúscula>

[corpo opcional explicando o 'porquê' e detalhes da mudança]

[rodapé opcional: BREAKING CHANGE: ... ou Closes #123]

Dicionário Completo de Tipos (Tags)

feat Features / Novas Funcionalidades

Adiciona um novo recurso perceptível para o usuário final ou API.

Ex: feat(auth): implementa autenticacao com OAuth2
SemVer: MINOR
fix Bug Fixes / Correção de Defeitos

Corrige um bug ou comportamento inesperado no sistema.

Ex: fix(cart): corrige calculo incorreto de frete para o Nordeste
SemVer: PATCH
docs Documentação

Alterações exclusivamente em documentação (README, JSDoc, Swagger, Wikis).

Ex: docs: adiciona guia de instalacao do Docker no README
SemVer: N/A
style Estilo & Formatação de Código

Atenção: NÃO é para CSS/Design! Refere-se a formatação de código (espaçamento, ponto-e-vírgula, linter).

Ex: style: formata codigo com Prettier e remove espacos extras
SemVer: N/A
refactor Refatoração de Código

Mudança estrutural no código que nem corrige bug nem adiciona feature (ex: Clean Code, extrair classes).

Ex: refactor: modulariza funcoes do banco de dados em repositorios
SemVer: N/A
perf Melhoria de Performance

Mudança de código focada em otimização de velocidade de execução ou redução de memória.

Ex: perf(db): adiciona indice composto para acelerar queries
SemVer: PATCH
test Testes Automatizados

Criação ou correção de testes unitários, de integração ou mocks (Jest, PyTest, JUnit).

Ex: test(auth): adiciona testes unitarios para validacao de senha
SemVer: N/A
chore Tarefas Rotineiras & Manutenção

Tarefas auxiliares que não afetam código de produção (atualizar dependências, arquivos .gitignore, etc.).

Ex: chore: atualiza dependencia do tailwindcss para v3.4
SemVer: N/A
build ci Build & Integração Contínua

Configurações de compiladores/bundlers (Vite, Webpack, Maven) ou pipelines (GitHub Actions, GitLab CI).

Ex: ci: adiciona workflow de deploy automatico no AWS S3
SemVer: N/A

Comparações Práticas: Commits Bons vs. Ruins

❌ Commits Ruins (Amíguos / Genéricos)
  • • "ajustes no sistema" (Sem prefixo e vago)
  • • "arrumando bug." (Com ponto e no gerúndio)
  • • "style: muda cor do botao" (Erro: UI é feat/fix)
  • • "feat: Adiciona login e ajusta css e altera banco" (Commit gigante com 3 responsabilidades)
✅ Commits Bons (Claros & Semânticos)
  • • "feat(auth): adiciona validacao de senha forte"
  • • "fix(login): resolve falha de redirecionamento 404"
  • • "feat(ui): altera paleta de cores do botao primario"
  • • "refactor(db): extrai conexao singleton em modulo"
